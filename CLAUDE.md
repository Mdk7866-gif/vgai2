# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

**vgAI** is an AI video-production SaaS: creators paste a script, split it into scenes, and generate matching images/animations/voiceovers per scene, reusing saved character and style-template libraries. Full product spec (all pages, features, and the credit system) is in [`README.md`](./README.md) — read it before implementing any feature, it's the source of truth for intended behavior. The full DB schema is in [`vgaidatabase.dbml`](./vgaidatabase.dbml).

**Current state: early build, not just scaffold anymore.** Auth (Supabase Google OAuth, an inline `LoginModal` gating write actions rather than a forced login redirect) and three full CRUD library features are implemented end-to-end, backend route + Pydantic schema + frontend page/card/edit-popup: **Characters** (`/characters`), **Style Templates** (`/style_templates`), and **Generate Scripts** (`/generate_script`, `script_templates`). Characters and Style Templates each have their "Generate with AI" flow fully built (see AI-generation pattern below) — **not Gemini as originally spec'd in `README.md`**, both use OpenAI (LangChain `ChatOpenAI` for text/structured output, `gpt-image-2` for character sheet images) via `app/openai_client.py`. `/generate_script` is a different, multi-step AI flow — research 10 viral topics (Perplexity `perplexity/sonar-pro`) → generate a full script + character list per chosen topic (Claude `anthropic/claude-sonnet-5`) → optional feedback-driven "Improvise" regeneration — both models called via OpenRouter (`app/openrouter_client.py`, `app/routes/scriptgenerationtemplate/viralscripttopicresearch.py`); its `POST .../create` save path (`app/routes/scriptgenerationtemplate/crud.py`) persists the *form inputs* as a reusable `script_templates` row, not the generated script itself — scripts stay ephemeral (frontend-only state) until a project exists to import them into (see its `/project_folder/{project_id}` import placeholder). Credit top-ups are also implemented end-to-end via Razorpay (`app/routes/payments/crud.py` — order creation + Checkout-signature verification; `app/routes/payments/webhook.py` is a documented, not-yet-registered backup path, see its docstring). Navbar and Sidebar are real chrome (not placeholders — see Frontend architecture below). Everything else described in `README.md`/`vgaidatabase.dbml` — projects, scene generation, liked projects, profile usage-history — is still unbuilt; those pages/sections exist only as "coming soon" stubs or are missing entirely. The home page (`/`) also still has leftover demo-popup buttons (Interactive Components section) from the original template — not a real feature, safe to delete when that section of the app gets built. Don't assume a feature exists in code just because it's documented in `README.md`; check the actual route/component first — `README.md`'s Tech Stack/§5 still says Gemini for the Characters/Style Templates flows, which is now stale.

## Backend architecture

- **Routing**: `app/main.py` creates the `FastAPI` app and mounts `app/routes/router.py`'s `api_router`, which aggregates per-resource routers (`app/routes/users.py`, `app/routes/characters/crud.py`, `app/routes/styletemplates/crud.py`, `app/routes/scriptgenerationtemplate/crud.py`, `app/routes/payments/crud.py`). Multi-endpoint resources live in their own subpackage (`app/routes/<resource>/crud.py` + `generate<resource>.py`). Add new resources the same way, and register the router in `router.py`.
- **AI-generation pattern** (`characters/generatecharacter.py`, `styletemplates/generatetemplate.py`): both `POST .../generate` endpoints follow the same shape — check `current_credit_balance` against a fixed per-call cost up front (402 if insufficient), call OpenAI, deduct credits + bump `miscellaneous_credit_spent` on success, and return the generated draft *unsaved*. The frontend shows an accept/reject preview (`GenerateCharacterSheetPopUp.tsx`, `GenerateStyleTemplatePopUp.tsx`); accepting re-submits the (possibly-edited) draft to the resource's normal `POST .../create` endpoint — generation never writes to the DB directly. `generatetemplate.py` also hard-truncates every generated field to its word-count ceiling after the LLM call, since prompting for a limit isn't a guarantee and an over-limit draft would fail `EditStyleTemplateCardPopUp.tsx`'s own validation on save/edit — keep those ceilings numerically in sync if either side changes. Both use OpenAI via `app/openai_client.py` (LangChain `ChatOpenAI` for text/structured-output, `gpt-image-2` for character-sheet images, `quality="low"`/`"high"` gated behind a "Generate with Pro" toggle on the character flow) — not Gemini, despite `README.md`. The backend balance check is the authoritative guard, but both Generate popups also call a `refreshBalance()` helper right before submit (re-fetches `GET /users/me`, aborts client-side with an error if now insufficient) — the balance shown on popup-open can go stale if the user's credits changed elsewhere (another tab, a top-up) while it sat open, and this avoids the wasted round-trip of hitting `/generate` only to get a 402 back.
- **`/generate_script` AI pattern** (`scriptgenerationtemplate/viralscripttopicresearch.py`): three independent, stateless `POST` endpoints under the same `/scripttemplates` prefix as the CRUD router — `/generatetopics` (Perplexity `sonar-pro`, flat `TOPIC_RESEARCH_CREDIT_COST` of 20), `/generatescript` and `/improvise` (both Claude `sonnet-5`, cost = `script_word_length`'s upper bound ÷ `WORDS_PER_CREDIT` (5), e.g. an "800-900" band costs 180 credits). Same balance-check-then-deduct shape as the AI-generation pattern above (`_check_and_get_balance()`/`_deduct_credits()` helpers), but no accept/reject-into-`create` step — nothing generated here is ever DB-backed; `/generatetopics` and `/generatescript`/`/improvise` results live only in `generate_script/page.tsx`'s React state (topic cards, script cards), and only the *form inputs* can be persisted, via the normal `POST /scripttemplates/create`. Both LLM calls go through `app/openrouter_client.py`'s `get_openrouter_chat_model()` (`ChatOpenAI` pointed at OpenRouter's `base_url`, same class as the OpenAI flows) — Claude calls use `.with_structured_output()`; the Perplexity call does not (uncertain tool-calling support), so `/generatetopics` instead prompts for raw JSON and parses it defensively (`_parse_topics_json()`, strips code fences / extracts the first `[...]` block) rather than trusting structured output.
- **Payments**: `app/routes/payments/crud.py` implements Razorpay credit top-ups — `POST /payments/create-order` creates a Razorpay order + a `pending` `credit_topups` row priced off a fixed `PAISE_PER_CREDIT` (INR-only; see its module comment for why), `POST /payments/verify` verifies the Razorpay Checkout signature and applies the credits. `app/routes/payments/webhook.py` is a written-but-unregistered backup path for the case where a payment succeeds but the user closes the tab before `/verify` fires — see its docstring for why it's inactive (needs a real deployed domain) and how to turn it on.
- **Config**: `app/config.py` defines a `pydantic-settings` `Settings` class loaded from `backend/.env`, exposed as a module-level singleton `settings`. `env.example` at the backend root is stale — it references an unrelated prior project's variables (`DATABASE_NAME`, `MAX_BULK_URLS`, `DOWNLOADS_DIR`) and does not match what the code actually reads.
- **Cloudinary**: `app/cloudinary.py` provides `upload_image()`/`delete_media()` helpers (config fields for cloud name/API key/secret/folder are declared on `Settings`). Assets upload to `<CLOUDINARY_FOLDER_NAME>/<user_id>/<resource>/...`; see `README.md` §9 for the full planned folder layout (only the `characters/` slice is wired up so far — style templates have no image field). `delete_media()` is best-effort (swallows errors) since a Cloudinary asset already gone shouldn't block a DB delete.
- **Supabase**: `app/supabase.py` exports a singleton `supabase` client built with the *secret* (service-role) key — it bypasses Row Level Security, so any per-user access scoping has to be enforced in route code, not assumed from RLS. The `_get_owned_<resource>` helper pattern in `characters/crud.py`/`styletemplates/crud.py` (fetch by id, 404 if missing or `user_id` mismatch) is how that scoping is done — follow it for new resources.
- **Schemas**: request/response models live in `app/schemas/*.py` as plain Pydantic models per resource. `character.py`, `styletemplate.py`, and `payment.py` are aligned to their DBML tables (plus the two `Generate*Request`/`Generate*Response` pairs for the AI-generation endpoints, which aren't DB-backed); other resources are not yet modeled.

## Frontend architecture

- **App Router + client-heavy pages**: routes live under `frontendweb/src/app/`. Existing pages so far use `"use client"` liberally (see `page.tsx`); shared chrome lives in `frontendweb/src/components/`.
- **Layout shell**: `layout.tsx` wraps every page in `ThemeProvider` → `SplashScreen` + `MainLayout`. `MainLayout` renders `Sidebar` + `Navbar` + page content + `Footer`, and owns the mobile sidebar open/close state (sidebar is an off-canvas drawer below `md:`).
- **Theme**: dark mode is a `dark` class on `<html>`, decided pre-hydration by an inline script in `layout.tsx` (reads `localStorage.theme`, falls back to `prefers-color-scheme`) to avoid a flash of the wrong theme. `ThemeProvider` (`components/ThemeProvider.tsx`) mirrors that into React state after mount and exposes `useTheme()`/`toggleTheme()` for interactive toggling; keep both in sync if you touch theme logic.
- **Sidebar/Navbar match the README spec**: `Sidebar.tsx` implements the `README.md` §4 structure — a Library section (Characters, Style Templates, Generate Scripts, Liked Projects) that's always visible/clickable even when logged out, and a Project Folders section that shows a login-gated message instead of the project list when logged out. `Navbar.tsx` has Home/About/Contact (no login required to view), a credit-balance pill (links to `/profile`) when logged in, and either an account-avatar menu or a "Login" button depending on auth state.
- **Public browsing, gated actions**: nothing forces a login redirect on page view — `(app)/layout.tsx` renders `MainLayout` regardless of auth state. Write actions (create/edit/delete/generate) call `requireAuth()` from `AuthContext` (`context/AuthContext.tsx`) first; if signed out, it opens the global `LoginModal` (rendered once from root `layout.tsx`) and returns `false` so the caller bails out. Follow this pattern for any new write action rather than redirecting to `/login`.
- **Characters/Style Templates are the reference pattern for new library resources**: each is `types/<resource>.ts` (interface matching the backend schema) + `components/<resource>/<Resource>Card.tsx` (grid card, edit/delete always visible — no hover-to-reveal) + `components/<resource>/Edit<Resource>CardPopUp.tsx` (create/edit form, remounted via a parent-owned `key` prop on open rather than resetting state in a `useEffect`) + `app/(app)/<resource>/page.tsx` (list/create/edit/delete wiring via `lib/api.ts`'s `authFetch`). Style templates additionally show a `Toggle` (`components/Toggle.tsx`) for `is_default` directly on the card, since only one template can be default at a time — see Domain model notes below.
- **"Generate with AI" popups follow a shared shape**: `components/characters/GenerateCharacterSheetPopUp.tsx` and `components/styletemplates/GenerateStyleTemplatePopUp.tsx` both go form → `generating` loading state (with an estimated wait-time hint) → accept/reject preview of the AI draft → "Accept & Save" re-submits to the resource's normal `POST .../create`, not a separate save path. Both check/display live credit balance (`GET /users/me`) and disable Generate when the balance is below that flow's fixed cost; keep the frontend's cost constant and the backend's `GENERATE_CREDIT_COST` numerically in sync when either changes — nothing enforces this automatically. `CreditCoinIcon` (`components/CreditCoinIcon.tsx`) is the one gold-coin glyph used for every credit reference app-wide (Navbar balance pill, `/profile`, `AddCreditsPopUp`, both Generate popups) — use it instead of an icon-library coin so credits read as the same in-app currency everywhere.
- **`/generate_script` breaks from the card+edit-popup library pattern**: it's a single-page multi-step flow, not CRUD-on-a-grid — `app/(app)/generate_script/page.tsx` owns one form (category/country/word-length/etc.) plus two *non-popup* result lists rendered inline: `SuggestionTopicCard.tsx` (one per researched topic, its own "+ Generate" button) and `GeneratedScriptCard.tsx` (one per generated script, stacks as the user tries multiple topics — shows script/word-count/character list and Import/Improvise buttons). Only `GeneratedScriptFeedbackPopUp.tsx` (the Improvise feedback prompt) and `ShowScriptTemplatesCardPopUp.tsx` (browsing saved `script_templates` to re-import into the form) are actual portaled popups. The "Import" button on `GeneratedScriptCard.tsx` is a placeholder (no `/project_folder/{project_id}` to import into yet) — wire it up once that page exists.
- **All overlay popups portal to `document.body`**: `AlertMessagePopUp`, `ConformationMessagePopUp`, `ImageZoomPopUp`, `LoginModal`, both `Edit*CardPopUp`/`Generate*PopUp` components, and the Navbar's account dropdown use `createPortal`. Do the same for any new full-viewport overlay or dropdown — a `position: fixed` element nested under an ancestor with a CSS `transform` *or* `backdrop-filter` (e.g. a card's `hover:-translate-y-0.5`, or the Navbar's `backdrop-blur-md`) gets clipped to that ancestor's box instead of the viewport, since the ancestor becomes the fixed element's containing block. This bit the Navbar's account menu specifically: its outside-click backdrop was confined to the 64px navbar bar, so clicks on the page below never closed it, until the dropdown was portaled out.
- **Important — Next.js version drift**: `frontendweb/CLAUDE.md` (`@AGENTS.md`) warns that this Next.js version has breaking API/convention changes versus training data. Read the relevant guide under `frontendweb/node_modules/next/dist/docs/` before writing or changing any Next.js code in `frontendweb/`.

## Domain model notes (see `vgaidatabase.dbml` for full schema)

- **Credits are the app's currency**: `100 credits = $1`. All AI actions (LLM, image, animation, voiceover, and one-off "miscellaneous" generations like character-sheet/style-template/script generation) are billed in credits against `users.current_credit_balance`. Script generation's cost isn't flat — it scales with the chosen `script_word_length` band (`WORDS_PER_CREDIT = 5` in `viralscripttopicresearch.py`), while topic research is a flat 20 credits regardless of inputs.
- **Snapshotting pattern**: when a project imports a character or style template, the data is copied into project-scoped tables/columns (`project_characters`, `projects.snapshot_styletemplate_*`) rather than referenced live — later edits to the library item must not retroactively change existing projects.
- **Spend history survives deletion by design**: `project_expence_tracker` stores `project_id`/`project_name` with no foreign key specifically so a project's credit-spend history remains queryable (for `/profile` usage history) after the project itself is deleted.
- **`is_default` cardinality differs by table**: `characters` has no uniqueness constraint, so a user can mark multiple characters default. `style_templates` has a partial unique index (`idx_user_default_style`, `WHERE is_default = true`) enforcing at most one default per user — the route layer must unset any existing default before setting a new one (see `_clear_existing_default()` in `styletemplates/crud.py`) or the DB write fails.
